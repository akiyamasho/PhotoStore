This follow-up addresses #23 and the latest row volume/duration requests.

- Video Timeline live drawing stays on the background compositor while new movie frames are prepared. Completed textures publish during renderer callback preparation without rebinding, and displaced resources retire off the UI thread.
- Recognized Normal RGBA8 stacks stream beyond eight inputs in bounded batches, preserving bottom-to-top source-over order and opacity. Unsupported effects/formats retain their portable fallback. The 64-input optimization ceiling does not cap document layers or promise arbitrary 4K throughput.
- Each audio/video row has an independent volume control. Gain persists separately from clip gain and mute; preview and export use both. Legacy projected audio is isolated by owner without flattening relative clip levels.
- Visible edge handles and duration feedback allow trimming videos and extending still/Smart Object holds. Extend Clips to Timeline End fills the existing span within source bounds.
- Timeline end follows content after editor, direct range, media insertion and audio clip timing edits. Blank audio-only layer ranges follow their remaining clip union; video/painted owners retain their authored visual range. Implicit legacy movies count as source-backed content when fitting. Duration/Add 5 seconds deliberately reserves extra time; extending content consumes the reservation. Fit Timeline to Content removes it. Trims preserve off-clip keys and markers; custom work areas remain bounded.

An unpublished candidate exposed a [Smart Object data-boundary failure](../performance/0.20.8-smart-before.json): converting one timed layer retained sibling memberships in its embedded timeline and native encoding correctly rejected it. Conversion now filters the child tracks to the copied subtree's clip ranges, preserving retained metadata/order. The corrected source must complete the production build and focused conversion/trim/save/reopen boundary before publication.

The first [native window run](../performance/0.20.8-native-before.json) exposed startup/redraw feedback while every display was asleep: roughly 1,400 UI constructions per second, three changed-video texture publications in a 4.56-second window, with real synthetic brush commit and camera pan. Its fixed 0.8-second pre-delay had not completed native preroll, so it is not a warm FPS result. The delayed-loading spinner requested immediate repaints; it is replaced by a quiet clock in the same fixed slot, leaving transport's bounded retries authoritative. A small raster paint layer also introduced the planner's local `CopyRect` flow and escaped the fused Normal path. Matching raster Content/Blend/CopyRect sequences now preserve exact source clipping in bounded texture batches; other copies/effects retain the generic renderer. A short owned-process profile informed these changes; no GUI recording or screenshot was taken.

Video transport now separates authored content revision from decoded presentation revision. Pixel-only edits keep the clock/preroll running; seeks and global timing changes retain synchronized preroll. Audio-relevant edits compare row/clip gain, source/timing, owner/link, curve and authored visibility metadata and keep synchronized reinitialization. This also applies volume changes after the undo-history count has reached its cap. The metadata signature is not rescanned for every decoded presentation. Canonicalizing an unchanged current property row no longer detaches the full shared frame bank.

The next [unpublished native candidate](../performance/0.20.8-native-19618.json) retained responsive brush/pan input but failed video cadence (two changed publications in 4.54 seconds). It is not a successful performance result. Decoder retirement now uses recent consumer requests as well as recent decode work: cached-frame polls during preroll keep a bounded stream alive rather than letting an active consumer expire. Retirement drops processes outside the shared cache lock. Timeline thumbnails are isolated from presentation frames and decoded to a bounded aspect-preserving preview rather than full 4K. Opt-in scalar media diagnostics stay disabled during normal startup.

The [c150 native window candidate](../performance/0.20.8-native-c150.json) improved decoder reuse and composition, but still failed cadence. The scheduling cause is separate from the cache-size policy: consumer-affine foreground workers also popped thumbnail jobs and could block behind the single background-decoder permit, leaving a required movie owner unable to run. Thumbnails now have one dedicated background worker and queued thumbnail work is suspended while native transport is active. The same shared decoder admission (at most four heavyweight decodes, one background) and memory allowance remain authoritative. In-flight thumbnail work finishes safely without occupying a foreground worker. Active transport suppresses new thumbnail work; pause/stop wakes it. This avoids creating a late-frame catch-up cycle during preroll/early playback.

Native per-frame timing history and decoder logging are explicitly opt-in diagnostics, disabled during ordinary startup and installation. The focused owned playback probe enables timing history without screenshots or recording artwork.

Forward native transport stages one next-frame document snapshot on the existing presentation worker while the canvas composes the current frame. Staging is not publication: it changes no document current frame, revision or history. The clock-due presentation consumes the validated snapshot. The single existing mailbox/generation guards bound work and invalidate it on authored edits/seeks; stale snapshots retire on the worker. No extra decode workers, frame window or memory allowance are added. This removes the serial decode/evaluate-then-compose start pattern that can push a near-budget frame late and trigger expensive raw-frame catch-up.

The [compact native candidate](../performance/0.20.8-native-compact-before.json) reached about 28–29 fps in its final panning/idle phases, but the full 4.55-second workload averaged 21.97 fps and failed cadence and brush acceptance. Four GPU texels matched original-quality CPU output within one U8 code value. Brush failure was traced to projected-tile identity checks falsely classifying unchanged compact movies as raster edits. Immutable pixel-storage identity now keeps edit guards and Smart Object/multi-layer comparisons off the projection path. NV12 crops also write directly into one mapped staging allocation, eliminating a temporary payload and duplicate copy. The corrected source requires native acceptance before publication.
