# PhotoStore 0.21.7

Large layered projects reuse verified raster tiles when opening a native document. Edited tiles detach on write. Animated Smart Objects share the media cache according to their estimated resident size, and independent nested videos can request their frames in the same presentation pass. Embedded animations without linked movies can reuse a completed composite at the same time. Nested linked movies retain their existing source validation.

The Metal compositor can batch eligible Normal stacks of up to 256 sources. It skips layers clipped outside the current cell, keeps unchanged raster textures resident within the configured budget, and checks the upload budget before staging each cell. Mixed blends continue through the general GPU renderer. Nested CPU compositing writes in bands to reduce temporary allocations.

The load fixtures and native measurement tool are in [scripts](../../scripts/). They exercise 4K documents with embedded animated compositions, nested movies and stills, independent top-level movies and over 100 layers. They also measure visible frame publication and check Brush and Move with the timeline open.

## Load-test results

One matched run per version and project on an Apple M1 Max using Metal. Values show 0.21.6 → 0.21.7. Each 3840 × 2160 project contained three top-level H.264 videos, twelve distinct animated Smart Objects, and another embedded composition inside each one with keyframed video and a still. The 140-layer project added 24 distinct 2560 × 1440 translucent raster layers to the 116-layer project.

| 116 layers, 2 seconds | 3.42 → 2.92 s | 637 → 408 ms | 3.0 → 10.7 | 1.05 → 0.96 GiB | 819 → 199 MiB |
| 140 layers, 345 MiB, 2 seconds | 3.74 → 2.98 s | 748 → 405 ms | 3.0 → 10.5 | 1.80 → 1.67 GiB | ~1.5 GiB → 412 MiB |
| 116 layers, 60 seconds | 1.39 → 1.13 s | 920 → 976 ms | 3.1 → 10.4 | 2.67 → 2.84 GiB | 655 → 176 MiB |

All 30 exact seeks on the release produced the requested Metal frame. With the timeline open, synthetic **B** and **V** key events selected Brush and Move in every project. Two exported frames from a nested animation, at frames 0 and 30, matched their respective 0.21.6 PNGs byte for byte. Six focused format, engine and GPU regressions passed, including CPU/GPU pixel parity after edits and with a constrained GPU budget.

Full-resolution playback remained below the 30 fps timeline rate. On the one-minute project, long-distance seeks took slightly longer and peak sampled process RAM rose by 0.17 GiB. Playback used more CPU while delivering more frames. On the dense project median process CPU rose from 185% to 226%, where 100% represents one core.

### Measurement details

The first-frame timer runs from opening a document to observing its first published GPU texture, including timeline-panel setup and inspection. Each of ten seeks waits for a new publication at the exact requested frame. Playback runs for eight seconds on the short loops and thirty seconds on the longer project. The frame rate uses the change in the native publication counter across that whole interval. The process sampler runs outside PhotoStore. The Mac uses unified memory, so process RSS and graphics residency overlap. The OS disk cache was warm and variable.

The benchmark used synthetic documents and control-channel input. Physical display timing, stylus input, audio sync and hour-long projects were outside the measured workload. An additional background profiling run on 0.21.6 stopped publishing while the window was occluded. The paired runs explicitly activated each disposable test window.
