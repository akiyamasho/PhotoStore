## Changes

- Persist a document-local media source catalog with stable IDs, revisions, path/size/modification fingerprints, stream metadata, offline/changed status, and explicit sync/relink operations. Insert media as editable source instances while preserving source identity.
- Correct a unity-speed audio filter separator that could make FFmpeg reject playback/export audio.
- Use rational project-frame-rate metadata with legacy compatibility, shared project-to-source presentation-time mapping, and exact-frame readiness for the timeline canvas. Coalesce current-frame work per consumer and bound forward prefetch for uniformly spaced frames.
- Account retained movie frames, UI thumbnails, and waveform data in a shared 256 MiB derived-cache budget; cap heavy media decoders at two active slots with priority for foreground frame requests.
- Add opt-in half/quarter disk proxies with a configurable limit capped at 10 GiB. Preview can use a current matching proxy; exports always use original sources.
- Preserve originals when materializing media into PNG/PSD exports, video/Smart rasterization, merge/flatten/stamp, or clipboard copy. Native `.pcraft` saves remain possible offline and retain source references and the last preview.
- Drive native 48 kHz stereo output from a bounded sample-clocked buffer when the device supports it, retaining the streaming external-player fallback.
- Support explicit affine Smart Object animation bake to editable frame content. Perspective/warp remains unsupported and guarded.
- Preserve original-source export, explicit background selection for transparent H.264 MP4 output, tagged Rec.709 SDR defaults, and actionable failure for unsupported HDR conversion.

## Limits and acceptance

The 256 MiB figure covers registered retained derived-media caches. It excludes document/layer pixels, transient decoding memory, unregistered GPU/driver allocations, and process overhead; proxy frames retain the original layer footprint. No total-RAM guarantee is made.

The current video decoder path uses an 8-bit intermediate. Unsupported HDR input requires a separately supported explicit tone-map workflow or fails; it is not silently clamped. Container names do not promise every codec. H.264 MP4 requires an explicit background where the output has alpha; MOV/WebM alpha depends on the selected supported encoder.

Five unique focused engine checks passed (four in the initial run, the corrected media-export check in its targeted retry); two format migration/roundtrip checks also passed. Native interaction/audio-device/export acceptance and measured performance targets remain pending; the production build and artifact verification passed. Do not infer them from source integration or the synthetic GPT Image reference. Issue #23 remains open pending final user workflow acceptance.
