# PhotoStore 0.20.1 — scalable timeline playback and authoring

**Status: published and initially installed; cadence defect found before native acceptance.**
[Stable v0.20.1](https://github.com/akiyamasho/PhotoStore/releases/tag/v0.20.1) targets exact source `72a4ddd131273357ce81a76af52c3abc8706e4ba`.
The normal app/CLI build, artifact verification, publication and atomic installation passed.
The production results subsequently exposed a timestamp-rounding defect: every third frame in the
30 fps fixture repeats its predecessor. This version improves preparation latency but does not
satisfy smooth/full-cadence playback. A follow-up correction is required; #23 remains open.
See [machine-readable evidence](../performance/0.20.1.json).

This source pass addresses the playback and fixed-size timeline-authoring limits reported in issue
#23. It retains PhotoStore's editable document, layer tree, Smart Object, timeline, and command
registry model. The design was generated and inspected before implementation; it is a design
reference, not a screenshot or performance result ([workflow board](../design/2026-11-01/smooth-playback/workflow.png),
[prompt and provenance](../design/2026-11-01/smooth-playback/prompt.json)).

## Source changes

- `Surface::convert` shares copy-on-write tiles when the complete pixel format is identical and
  converts samples directly when only the sample depth changes within the same channel model and
  alpha layout. Genuine color-model conversions retain the existing semantics. Movie decoding
  caches the supported byte transfer ramps and CMS transforms rather than rebuilding that work for
  every frame.
- Forward preview uses a persistent sequential FFmpeg decoder per consumer/source configuration
  and publishes each ready frame separately, rather than waiting for an entire requested window.
  Two worker threads share a maximum of two active heavy-decoder permits; each worker retains at
  most two parked streams, retiring an idle stream after two seconds. Requests are source-revision,
  timestamp, format, output-size and consumer qualified. Foreground playback outranks background
  work; seeks, relinks, discontinuous mappings and stale generations cannot relabel an old frame as
  the requested one. Exact sampling remains the fallback for mappings a sequential stream cannot
  serve.
- Presentation readiness avoids building a candidate document for a cache miss. One candidate is
  retained for its exact pending presentation while nested/Smart work becomes ready, then committed only when its required frames are ready.
  The transient UI playhead and timecode follow the audio/monotonic playback clock while the canvas
  remains on its last ready document frame and reports buffering. Cold filmstrip, animation-frame,
  and source-card thumbnail work is skipped during playback while resident thumbnails stay visible.
- Retained movie frames, Smart previews, thumbnails and waveforms now borrow one adaptive derived
  media budget. Its target is one quarter of the existing Memory Usage allowance, capped at one
  eighth of detected physical RAM, with a 16 MiB floor. Categories can borrow available shared
  space; there is no fixed 64 MiB thumbnail partition or 256 MiB total derived-cache ceiling. This
  target accounts retained derived media only, not all application memory.
- Frame and property snapshots use copy-on-write snapshot banks. They serialize as the same v3
  array-of-arrays data, share unchanged banks across document/history clones, detach on mutation, and
  report unique-bank memory to history accounting. The four timeline operations that formerly
  rejected estimates above 64 MiB now use the configured Memory Usage allowance, checked/fallible
  reservations, cancellable background jobs, progress, and atomic commit/undo semantics.
- Recording frame codec allocation is estimated from the configured output geometry instead of a
  fixed 64 MiB per-frame check. The 100,000-frame and 256 MiB recording-archive limits remain.
- `media.performance.measure` measures 2–600 exact presentation requests from a caller-supplied
  local media path. It reports cold-first and warm p50/p95 preparation latency, prepared frames per
  second, decoder launches, sampled-pixel diversity and retained derived bytes. It runs headless;
  Ambient file measurement is restricted to trusted local UI/CLI use; untrusted automation cannot
  read an arbitrary path through this diagnostic. It does not measure native GPU composition, UI paint/input, display scheduling, audio-device
  output, or CapCut-equivalent playback FPS.

## Existing limits and acceptance

The source decoder still uses an 8-bit intermediate. HDR needing unsupported tone mapping fails
explicitly. The 64-megapixel Smart affine-transform guard remains; a tiled/preflight renderer is
needed before safely changing that limit. Recording still caps archives at 256 MiB and 100,000
frames. Native archive loading defaults to a 256 MiB manifest, 1 GiB per blob and 16 GiB total,
subject to `LoadOptions`; codec and decompression bounds remain in force. These are distinct from
the removed timeline-operation 64 MiB thresholds and the adaptive retained-media cache.

The pre-change baseline is recorded in the local receipt
`/private/tmp/photostore-playback-before-0.20.0.json` (not a repository asset): on
an Apple M1 Max / 32 GiB host, warm blocking exact presentation averaged 640.39 ms for a 1080p/30 fixture
and 1,929.93 ms for a 4K/30 fixture (five noninitial requests each). This CLI path excludes native GPU/UI/audio output
and is not playback FPS. The comparable signed production CLI reduced those warm means to
99.20 ms and 152.07 ms, respectively. Sequential 180-request preparation recorded warm p95 1.46 ms
at 1080p and 12.16 ms at 4K with one decoder each. However, only 120 sampled hashes were distinct;
direct original-frame comparison confirmed repeated frames from nanosecond time-base rounding.
These throughput numbers cannot establish complete 30 fps cadence or native smoothness.

Eleven focused critical checks passed, including >64 MiB authored metadata save/reopen/undo,
configured-budget atomic failure, exact export/Smart/proxy boundaries, COW and tight-cache
backpressure. The trusted-local diagnostic permission boundary also passed on the signed CLI.
The cadence finding requires an additional original-frame-by-frame regression and corrected release.
