# PhotoStore 0.18.0 — In-app GitHub updater

Status: **published stable release**. Tag `v0.18.0` points to source commit
`1da682ebd22981c39ef60b9df1d7ef12c3a4f04a`. The verified arm64 macOS app DMG and CLI ZIP were
installed locally and published on GitHub on 2026-10-18.

The 0.18.0 source adds **Help → Check for Updates…** to the native Apple Silicon macOS app. It
checks stable releases from the fixed private `akiyamasho/PhotoStore` repository using the user's
existing GitHub CLI (`gh`) authentication. It does not embed credentials. The published 0.17.1 app
does not contain this updater.

Before install, the updater downloads the architecture-matched DMG, verifies the release SHA-256,
mounts the image read-only, checks bundle identity and version, and requires strict code-signature
verification. Installation is refused while document tabs or jobs are open. A helper waits for the
app to quit cleanly, stages the verified bundle, preserves a recoverable backup, and rolls back when
activation fails. It does not force-quit the app or edit the incoming signed bundle after checking
it.

For paths present in both versions, the updater preserves the installed bundle's xattrs, POSIX
modes, ownership, file flags, and ACL state, including a user's removal of `com.apple.quarantine`.
New release paths follow the installed bundle root's quarantine policy. If the updater cannot prove
it preserved metadata safely, installation stops before renaming the original app. It retains the
incoming code-signature attributes and does not copy old FinderInfo or resource-fork metadata when
that would change the signed bundle. It does not migrate macOS TCC/privacy identity grants; a
signing or identity change may require renewed user consent.

The updater implementation passed engine/UI checks and the native command
`cargo check -p photostore -p photostore-automation --locked`; the metadata helper's standalone
synthetic harness passed three focused tests for xattrs, permissions, ACLs, quarantine policy, and
symlink safety. A first release compile exposed a missing mutable binding in the check-start error
path. The binding was restored in the tagged source and the release build then succeeded from that
exact commit. The checks above preceded release version preparation; the corrected version-bumped
source was built once for these artifacts. No full test suite was run.

The release app, CLI, and DMG passed `codesign --verify --strict`. They are ad-hoc signed and not
notarized. The helper installation returned exit code 0, rechecked metadata and signature before
atomic replacement, accepted the app launch request, and a new app process was observed. The CLI was
reinstalled atomically; the installed CLI reports `photostore-cli 0.18.0`.

GitHub's browser download and the updater's in-app self-update flow were not tested; installation
was from the local release artifact. TCC/privacy grants were not migrated or tested. The release
notes and [SHA256SUMS](https://github.com/akiyamasho/PhotoStore/releases/download/v0.18.0/SHA256SUMS)
record the published artifact digests.
