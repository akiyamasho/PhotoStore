# PhotoStore 0.20.4 — layered media playback

**Status: release source in preparation.** Build, measurement, publication and normal app/CLI
installation receipts will be added after delivery. No native performance parity is claimed.

- Timeline rows follow Layers top-to-bottom order, including hierarchy and authored tracks,
  without changing source timing or compositing order.
- Direct linked-video opacity edits gain a serializable static owner so older frame snapshots
  cannot reset the value during overlapping playback. Explicit animation remains available.
- Per-source movie audio and standalone audio layers retain independent timing, mute and gain.
  Audio-only rows use empty transparent raster storage and an optional serialized track owner,
  preserving the native document format and avoiding a 4K pixel allocation for a sound file.
- Reusable sequential decoder sessions share an accounted memory allowance and a bounded pool;
  active decode work remains capped at two workers. Multi-source headless measurement reports
  changing frames, authored properties and estimated retained costs separately from native FPS.

The [architecture/acceptance plan](../plans/layered-media-2026-11-01.md) records source ownership,
compatibility and performance limits. The [GPT Image reference](../design/2026-11-01/timeline-order/workflow.png)
and [exact prompt/inspection](../design/2026-11-01/timeline-order/prompt.md) preceded implementation.
The generated image is a synthetic design reference, not a product screenshot.

Native playback/compositing/audio-device behavior and target-machine 4K throughput remain manual.
Retained cache/session estimates are not a total process-memory cap. Codec, HDR, archive,
Smart-transform and native input limitations documented in earlier releases remain applicable.
