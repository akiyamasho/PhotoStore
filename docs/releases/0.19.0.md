# PhotoStore 0.19.0 — Timeline workflow and issue fixes

Status: prepared source for an authorized stable ARM64 macOS app-and-CLI release. The final source SHA, artifact verification, publication, and installation receipt will be recorded after delivery.

This release brings the timeline overhaul and the complete seven-issue source inventory into the normal PhotoStore installation. It includes the existing media/Smart Object inspector and keyframe workflow, brush smoothing correction, PSD/PSB timelapse metadata, app-switch cursor recovery, rename text clipboard routing, one-pixel brush decrease, and the required GPT Image design workflow. Additional timeline changes and exact evidence are recorded below after integration.

Routine local delivery now overwrites `/Applications/PhotoStore.app` directly using production identity and configuration. The legacy dev watcher is stopped; existing app sessions, artwork, preferences, and recovery state are preserved. The local-CI scheduler remains disabled and unloaded, with no pending work; publication must never trigger another build.

## Timeline enhancements in this source

- Explicit Video Timeline / Frame Animation mode menus, responsive compact toolbar/overflow, adaptive ruler ticks, one shared 180-point track gutter, larger media lanes, and readable clip-label overlays. Filmstrip and waveform work is limited to the visible clip range.
- Explicit Ripple Delete for visual and audio clips through the registry's optional `ripple` parameter. Ordinary Delete keeps its existing behavior. Ripple edits preserve following animation timing and linked audio, respect locks/bounds, and commit as one undoable transaction.
- Linked movie preview, filmstrips, and export use the same source-time mapping without an intermediate nominal-frame rounding. The decoder selects a held presentation frame; interpreted frame rate and source trim remain compatible with existing metadata. Resident frame stacks retain their ordinal mapping. This is not a claim of a new rational-time persistence format.
- Queued canvas movie requests coalesce per explicit consumer and take priority over thumbnails. Anonymous/nested Smart Object requests remain independent, including two instances of one child source sampled at different times. Active decoding is not forcibly cancelled. A 64-source metadata LRU avoids repeated ffprobe processes for warm timestamp requests. The 160 MiB resident movie-frame budget and bounded request queues remain; no measured speed or total-process memory claim is made.

The source, layer/Smart Object, clip, and track model remains shared with the existing document/command system. A new source-asset database, serialized rational project clock, disk-proxy UI, unified 256 MiB process budget, and performance benchmarks remain design proposals, not shipped controls or verified claims. Perspective/warp animation and baking Smart Transform keys to Frame Animation remain unsupported and guarded.

## Focused data-boundary evidence

A disposable 2×2 RGB FFV1 fixture contains a red frame at 0 s and blue frame at 1 s. Direct accurate seeking at 0.5 s returned blue (the following frame); the corrected held-presentation strategy returned red at 0/0.5 s and blue at 1/1.5 s. This verifies the timestamp selection strategy on synthetic local media only, not native UI, arbitrary codecs, or color/HDR acceptance.

The focused ripple-delete regression covers a non-Main track while Main magnet is enabled, preserved keys/linked audio, rejection of a locked suffix with no partial edit, one-step undo, and refusal to shift linked audio independently of its video. The exact focused filter `timeline_editor_cmds::ripple_delete_tests::ripple_delete_moves_non_main_clips_audio_and_keys_atomically_with_main_magnet_enabled` passed 1/1 (0.01 s runtime, 144.489 s including compilation); 1,151 other tests were filtered out.
