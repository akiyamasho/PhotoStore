# PhotoStore 0.20.6 — video transform and responsive timeline interaction

**Status: pushed, published and atomically installed as the normal app/CLI.** [Stable v0.20.6](https://github.com/akiyamasho/PhotoStore/releases/tag/v0.20.6) targets exact source [`e06c8ae5d66db99bf43b76a3a91b2f9b9c5a6508`](https://github.com/akiyamasho/PhotoStore/commit/e06c8ae5d66db99bf43b76a3a91b2f9b9c5a6508). The running app/session was preserved; restart manually when convenient to load this code.

- **#36 — video resize:** active Free Transform owns pointer drags ahead of Zoom and Rotate View. Video layers store a static source-to-layer homography, applied before timeline translation on every frame and preserved by the native format. Original resident frames and linked files remain unchanged. Whole-layer transforms update linked masks. Painting on a transformed video cache is rejected until rasterization, preventing a reduced preview from replacing original source pixels. Current video resampling uses bicubic interpolation; animated transform keys remain a Smart Object feature.
- **#37 — Space:** active video timelines accept play/pause from ordinary panels and focused controls without requiring a previous timeline click. Actual drawing-canvas focus reserves Space for hold-Space panning; pointer hover alone does not. Text entry and modal controls retain their keys. Repeated keydowns do not repeatedly toggle playback.
- **#38 — Layers workflow:** removed the separate Media/Import sidebar and its toggle. Existing layers, clip context actions, File Place and dropping files remain the media workflow. Older saved `media_open` UI fields are ignored.
- **#23 — buffering:** native presentation preparation runs on one retained worker with one latest queued request. Source metadata, working-space conversion, Smart Object refresh and placed-frame preparation no longer run in the UI poll. Completed results must match document, content revision, navigation origin and target frame before publication; navigation preserves history and clean state.
- Native video GPU composition uses worker-private resources, including CPU band fallback. The UI retains the previous complete canvas while the worker prepares another output. Publication briefly swaps textures and rebuilds their bind groups against the receiving layout; the published texture is not simultaneously written as the next back buffer. GPU completion waits stay on the worker. One active request, one latest queued request and one completed result bound buffering; edits/seeks reject stale results.
- Audio mix-range scanning, device/process startup, polling and teardown run on one persistent manager. Generation-scoped handles make stop/replacement nonblocking and prevent stale startup from reviving a cancelled preview. Initial playback waits for the first complete canvas and asynchronous audio setup before anchoring its clock.

The changes preserve original resolution, authored layer data, source audio ownership and editable Smart Objects. They do not imply a new 4K throughput result or measured native input/display latency. The 0.20.5 headless throughput receipt is historical and cannot verify these native UI paths. User manual acceptance remains necessary for resize handles, Space focus behavior, responsiveness and sound output. Pan/Cintiq acceptance remains tracked in #30/#31.
